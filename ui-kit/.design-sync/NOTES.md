# Notes

- `[FONT_MISSING]` for "Cascadia Mono": accepted as-is, per user OK (2026-09-11). The mono stack is `ui-monospace,'Cascadia Mono',Consolas,monospace` — no webfont is bundled, so the DS pane renders mono text via the `ui-monospace`/`Consolas` fallback. No `cfg.extraFonts` entry added.
- Fixed during the solo preview pass (2026-09-11): every v2 component (`src/v2/components/*.tsx`) was rendering blank for any `go`/`due`/`closing`/`awaiting`-toned element. Root cause: `src/v2/tokens.css` scopes the whole v2 palette under `[data-palette="v2"]`, but no ancestor in the preview harness (or in any consuming app) ever sets that attribute, so `var(--go)` etc. resolved to nothing (at the time, `--text`/`--line`/`--panel2` still resolved from the old v1 stylesheet, since removed, which is why "neutral"-toned pieces looked fine while accent-toned pieces vanished). Fix: every v2 component's own root DOM node now carries `data-palette="v2"` directly, so each one is self-contained regardless of what wraps it. If a new v2 component is added later, it needs this too — grep `data-palette="v2"` across `src/v2/components/` to confirm coverage.
- Found independently by all 4 parallel preview-authoring batches (2026-09-11): both `.ds-sync/package-capture.mjs`'s review sheet and the real generated `<Name>.html` picker cards hardcode `body{background:#fff}`. This library is dark-native by design (`[data-palette="v2"]{color-scheme:dark}`) — any component with no *own* opaque background (relies on the app's ambient dark page instead, e.g. `QueueRow`'s title, `DetailHeader`, `StatGrid`'s untoned values, `FactRows`, `ContactRow`, `Timeline`, `Callout`) renders near-invisible light-on-white text in both the grading sheet and the picker card. Components that carry their own explicit background (`TopBar`, `StatusPill`, `ActionButton`) are unaffected. **Fix applied**: rather than patching the shared `.ds-sync/` harness (would need re-forking on every re-sync) or the component CSS (would add backgrounds these primitives correctly don't own — they're meant to be transparent, ambient-background pieces, matching the real shipped app), every affected preview in `.design-sync/previews/*.tsx` now wraps its exports in a small `<div style={{background:'var(--ink)', padding:16-20}}>` (plus `data-palette="v2"` on that wrapper for v2 previews) — i.e. composing each preview on the same dark ground the component actually ships against, per the "compose context-required pieces inside their parent" pattern. All affected cells re-graded `good` after this. **If this pattern recurs for a future component**: same fix — wrap the preview's export(s) in that ground `<div>`, don't touch `.ds-sync/` or add a background to the component's own CSS.
